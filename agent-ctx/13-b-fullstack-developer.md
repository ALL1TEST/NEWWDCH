- Read worklog tail (Task 12 RTL fix context) and confirmed the canonical i18n pattern: `const { t } = useT(); ... t('namespace.key')` imported from `@/lib/i18n`. Existing keys audited via `grep` against `src/lib/i18n/fragments/en/client-content.ts` (articles.* + media.* namespaces) and `src/lib/i18n/core/en.ts` (common.* keys like cancel/edit/delete/status/back).
- Read all 4 target files completely (content-edit-page 1268 lines, content-create-page 1226 lines, content-detail-page 280 lines, media-detail-page 551 lines) and inventoried every hardcoded user-facing string: JSX text, placeholder=, title=, aria-label=, label=, toast.success/error/info, SelectItem labels, button text, empty-state text, dialog titles/descriptions, accordion section labels, AI quick-action chips, toolbar buttons, confirm dialogs.
- **Strategy decision**: AI_NORMAL_ACTIONS / AI_SELECTED_ACTIONS were arrays of English strings used BOTH as backend IDs (sent to `/api/content/ai-generate` and `/api/content/ai-edit-selection`) AND as displayed labels. Refactored to `{ id, key }` object arrays so the backend continues to receive English IDs while the UI displays `t(action.key)`. This preserves backend behavior (no breaking changes to AI endpoints) while internationalizing the visible chip labels. Backend prompt interpolation also kept in English (e.g. `setPrompt(action.id)`).
- **Strategy decision**: The 4 shared sub-components (`PreviewPanel`, `MediaLibraryDialog`, `ScheduleDialog`, `AIAssistDialog`) didn't have `t` access. Added `const { t } = useT();` directly inside each sub-component (cleaner than prop-drilling).
- **Strategy decision**: For interpolation strings (deleteArticleConfirm with {title}, deleteMediaConfirm with {name}, tagCreatedToast with tag name), used `t(key).replace('{placeholder}', value)` pattern since the i18n `t()` function returns a plain string with no interpolation support. The dictionary entries use `{title}` / `{name}` placeholder syntax.
- Added `t` to the dependency arrays of `captureAndHandleQuickAction` and `submitWithStatus` in both content-edit and content-create pages (they now reference `t('articles.untitled')` / `t('articles.textDuplicatedToast')` etc.).
- Reused existing keys where the value matched: `articles.author`, `articles.tags`, `articles.noTags`, `media.altText`, `media.caption`, `media.copyUrl`, `media.download`, `media.deleteMedia`, `media.updateFailed`, `media.deleteFailed`, `common.cancel`, `common.delete`, `common.edit`, `common.status`.
